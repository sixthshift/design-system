# Palette takes

</div>

Seven premises for where a design system's colour comes from. Every one of them
is shipping in something you have used.

They differ less in which hues they pick than in **how much identity the default
asserts**, and — separately — in **whether the structure survives you changing
the hues later**. For a system meant to start many projects, the second axis is
the one that pays.

Nothing on this page ships. Six of these palettes do not exist in
[tokens.css](?path=/docs/design-system-theme--docs); they are candidates,
generated from the same spine as the real one so that the comparison is about
the premise rather than about which was built more carefully. The decision they
feed is `plans/10-default-palette-premise.md`.

Not a palette but a contract. Twelve steps, each holding a fixed job, so every
hue in the system ships the same twelve promises — and a component asking for a
solid fill never needs to know which hue answered.

<StepContract />

The consequence is the whole argument. Below is one structure with one value
changed; nothing else was re-tuned, and nothing downstream knew.

<div className="sb-unstyled grid gap-3 sm:grid-cols-2">

  <Vignette palette={{ ...takeById("anchored").palette, accent: takeById("expressive").palette.accent }} mode="light" label="accent: violet" />
</div>

**Ships in** Radix Colors. **Breaks when** twelve steps is more than most
components need, and the discipline only pays once several hues exist. It is a
structure, so it says nothing about what the thing looks like — that is still a
choice you have to make.

## Where this lands

**Structure from 07, temperature from 02.**

The step-semantic contract is the only item here that is not a matter of taste.
A hue swap becoming a one-line change with nothing downstream to re-tune is the
working definition of a starting point.
[Theming](?path=/docs/design-system-theming--docs) already applies that thinking
to *meanings*; extending it to *steps* costs one rewrite and pays for every theme
after it.

Then pick a temperature and hold it everywhere, the grey included. That part is
a taste, and it is the part that stops a system reading as generated.

One to keep in the back pocket: **03 is the sleeper if this is ever audited.**
The US Web Design System makes accessibility a property of the construction
rather than something verified afterwards — a stronger version of what
`bun run check:contrast` does today, which checks an outcome rather than
guaranteeing one.
